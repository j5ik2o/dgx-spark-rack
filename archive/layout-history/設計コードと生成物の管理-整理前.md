# 設計コードと生成物の管理

設計の正本（SSoT）はPythonの設計コードと寸法定義です。FCMacroは実行入口とし、FCStd・STEP・STLはそこから生成します。

## 対象と移行状況

| 対象 | 正本 | 現在の状態 |
|---|---|---|
| アダプタースタンド | `scripts/freecad_adapter_stand.py`、`scripts/freecad_features.py`、`scripts/adapter_stand_parameters.py` | コードから新規生成・検査・出力できる |
| アダプターラックv2 | `scripts/freecad_adapter_rack.py`、`scripts/adapter_rack_parameters.py` | 縦横連結、列ごとの120mmファン、ケース用取り付け面を生成する |
| 本体ラックv1 | `DGX-SPARK-RACK-FREECAD-v1.FCStd` | 旧生成コードは削除済み。コード移行前の例外として保全する |
| ファンコンケース | 未特定 | 既存設計の入手先を確認してから生成経路に組み込む |

本体ラックの次版で採用する片側0.20mmの接合隙間は、まだ本体ラックv1へ反映していません。既存ラックv1のSTLは片側0.30mmのままです。アダプターラックv2の縦横連結・120mmファン対応は別の生成経路で追加しました。アダプターラックの接合部は別設計なので、本体ラックの試験結果をそのまま転用せず、専用試験片で隙間を選びます。

## ファイルの責務

- `adapter_stand_parameters.py`：生成に使う寸法値・式・説明。寸法変更はここを編集する。
- `freecad_adapter_stand.py`：部品のスケッチ、加工、組立配置を定義する。
- `freecad_features.py`：拘束付きスケッチや加工の共通処理。
- `design/adapter-stand/adapter_spec.json`：購入品の参照実測値と出典。設計寸法そのものの変更先ではない。
- `build_adapter_stand.py`：新規文書の作成、出力先の選択、検査と来歴の記録をまとめる。
- `export_adapter_stand.py`：渡された文書を検査してFCStd・STEP・STL・画像へ出力する。既に開いている別文書を入力にしない。
- `run_adapter_stand.FCMacro`：上記を呼ぶ薄い入口。同じFreeCADセッション内でも編集したモジュールを読み直す。

## 再生成

アダプターラックv2は `scripts/run_adapter_rack.FCMacro` から `build/adapter-rack/<実行ID>/` に生成します。検査は `validate_adapter_rack.py`、出力処理は `build_adapter_rack.py` です。[v2ガイド](../../models/adapter-rack/docs/設計と組立.md)に構成と印刷部品を記載しています。以下は保全した旧スタンドの生成手順です。

FreeCAD GUIで `scripts/run_adapter_stand.FCMacro` を実行します。毎回新しい文書を作り、`build/adapter-stand/<日時>-<識別子>/` に出力します。既存の出力フォルダを明示指定した場合は上書きせずエラーになります。

FreeCADのPythonコンソールでは、次の方法でも実行できます。

```python
from pathlib import Path
import sys

root = Path("/このリポジトリの絶対パス")
sys.path.insert(0, str(root / "scripts"))
from build_adapter_stand import build
output = build()
```

通常のPython単体ではFreeCADモジュールを読み込めません。FreeCAD GUIと、そのバージョンに対応するPython環境が必要です。`build(render_images=False)` は画像出力だけを省略します。現在のモデルは表示属性も生成するため、この指定でもFreeCAD GUIモジュールの初期化が必要です。

## 出力と合格条件

| 出力 | 内容 |
|---|---|
| `DGX-SPARK-ADAPTER-STAND.FCStd` | 履歴・寸法式付きモデル。初期表示は2台 |
| `assembly-two-units.step` | 参考アダプターを含む2台組立 |
| `step/*.step` | 4種類の印刷部品。STLと同じ造形方向・原点 |
| `stl/*.stl` | 4種類の印刷部品。単位mm、各軸の最小座標0 |
| `two_units.png`、`four_units.png`、`stand_only.png` | 通常実行時の配置画像 |
| `validation.json` | 拘束、ソリッド、干渉、配線余白、寸法変更と復元、保存後の再読込 |
| `stl_validation.json` | STLの閉じた形状、接続成分、体積、外形 |
| `manifest.json` | 成功状態、FreeCAD版、元コードと出力のSHA-256 |

`manifest.json` は全検査の成功後だけ作成します。途中で失敗した実行フォルダは診断用で、印刷に使いません。ファイルのハッシュは来歴の確認用です。FreeCADやSTEPに日時等が入るため、同じコードでもバイナリが毎回一致する保証はありません。再現性はパラメーター、部品体積、寸法、ソリッド数などの幾何情報でも確認します。

## 変更の流れ

1. 設計コードと寸法定義を編集する。
2. マクロで再生成し、検査結果と形状を確認する。
3. 接合試験片や必要な部品だけを印刷し、結果を記録する。
4. 採用するコードを保存する。生成物を配布する場合は同じ実行のmanifest・検査結果を添える。

生成したFCStdの寸法表は試行のために編集できます。ただしGUIだけの変更は次回生成で再現されません。採用する値は必ずPythonの寸法定義へ戻して再生成します。

`exports/` とルートの既存FCStdは従来版の保存物です。新しい生成処理から自動で置き換えません。3MFは造形方向・個数・フィラメント・ブリムなどの印刷工程の記録として保持し、STLの更新後は必要に応じて作り直します。

## 基盤整備時の確認

2026年9月22日、FreeCAD 1.1.3で2回生成し、2台・4台構成の検査結果、寸法変更と復元、再読込結果、STLハッシュの一致を確認しました。従来版との組立寸法・部品体積も一致しています。配置画像の生成、ソースと出力のmanifestハッシュ、既存出力への上書き拒否も確認しました。

検証用にFreeCAD付属PythonへGUIを組み込んだ実行では、生成成功後のQt終了処理でクラッシュが起きたため、検証プロセスでは文書を閉じてから即時終了しました。この回避処理は設計コードには含めていません。通常の入口はFreeCADアプリ内のFCMacroです。offscreenプラットフォームでのGUI初期化も、この環境では動作しませんでした。
