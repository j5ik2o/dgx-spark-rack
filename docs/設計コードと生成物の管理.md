# 正本と生成物の管理

現行モデルの入口は [README](../README.md) の3行の表です。**形状を変えるときは `models/<モデル名>/source/`、印刷条件を変えるときは `print-projects/<モデル名>/<prototype または production>/` を使います。**

## 設計・生成物・印刷設定を混ぜない

```text
models/
  spark-rack/
    source/        本体ラックの正本Python・寸法定義・FCMacro
    docs/          本体ラックの操作・試作ガイド
  adapter-rack/
    source/        アダプターラックの正本Python、寸法定義、FCMacro
    reference/     購入品の仕様と出典
    docs/          アダプターラックの設計・組立ガイド
  fan-controller/
    source/        ケースの正本Python・FCMacro・生成処理
build/
  spark-rack/      正本Pythonから実行ごとに生成するファイル
  adapter-rack/    正本Pythonから実行ごとに生成するファイル
  fan-controller/ 正本Pythonから実行ごとに生成するファイル
print-projects/
  spark-rack/      prototype/ は試作、production/ は本番の印刷設定3MF
archive/
  adapter-stand-v1/ 旧スタンドのコード・資料・保存済み生成物
  print-projects/   失敗した混在配置や変更前のバックアップ
  build-history/    整理前のローカル生成履歴
  layout-history/   整理前のリポジトリ説明
tools/cad/         共通のCAD補助・検査処理
docs/              リポジトリ全体の運用ルール
```

`reference/`の実測値は設計寸法の根拠です。設計へ採用する値はPythonの寸法定義を編集します。FCMacroは実行の入口で、形状定義はPythonへ置きます。

## 本体ラックとファンコンケースもPythonから生成する

本体ラックは `models/spark-rack/source/run_spark_rack.FCMacro`、ファンコンケースは `models/fan-controller/source/FanControllerCase.FCMacro` をFreeCADで実行します。各モデルの `build/<モデル名>/<実行ID>/` に出力します。

本体ラックの旧FCStd・生成物は `archive/spark-rack-fcstd-v1/`、ケースの取り込み前マクロ・画像・検査記録は `archive/fan-controller-import/` に保全しています。現行コードはこれらを読み込みません。本体ラックの生成FCStdの寸法表は生成時の記録です。ケースの寸法定義は正本Pythonの冒頭にあります。

## アダプターラックはPythonから生成する

FreeCAD GUIで `models/adapter-rack/source/run_adapter_rack.FCMacro` を実行します。編集後のモジュールを読み直し、新しい文書を作成して `build/adapter-rack/<実行ID>/` に出力します。

Pythonコンソールから実行する場合は次のとおりです。

```python
from pathlib import Path
import sys

root = Path("/このリポジトリの絶対パス")
sys.path.insert(0, str(root / "models/adapter-rack/source"))
from build_adapter_rack import build
output = build()
```

FreeCADと対応するPython環境が必要です。画像生成を省く `build(render_images=False)` もGUIモジュールを使います。生成したFCStdの寸法表で試した値を採用するときは、正本のPythonへ戻して再生成します。

出力フォルダに成功状態の `manifest.json` があることを確認してください。manifestにはFreeCAD版、入力ソースと生成物のSHA-256を記録します。失敗した実行フォルダは診断用で、印刷に使いません。同じコードでも保存日時等でバイナリが変わるため、再生成の比較には部品体積・寸法などの幾何情報も使います。

`build/` は3モデルともローカル出力としてGit管理対象外です。旧スタンドを再生成する場合はアーカイブ内の入口を使い、出力も `archive/build-history/adapter-stand/` に置きます。現行の `build/` へ旧モデルを混ぜません。

## 印刷設定と旧版を扱う

3MFは形状の正本ではなく、造形方向・個数・フィラメント・ブリム等の記録です。現行のファイルと用途は [print-projects/README.md](../print-projects/README.md) に記載します。モデル更新後も3MFは自動更新されません。

採用しなくなったモデルは、コード・仕様資料・説明・保存済み生成物をまとめて `archive/` へ移します。旧モデルを現行の生成スクリプトや参考パラメーターとして暗黙に参照しません。共通CAD処理だけは `tools/cad/` を利用します。

過去の検査記録やmanifestに残る移動前のパスは、当時の記録として保持します。現行のリンク・生成処理・新しいmanifestは新配置を使います。今回の整理前の説明は `archive/layout-history/`、ローカル生成結果は `archive/build-history/` に退避しています。

## 検証の範囲

各モデルの検査結果には実施した検査だけを記録します。ケースではCAD形状、本体と蓋の干渉、再読込、STLの閉じた形状を検査します。実物の適合・耐荷重・耐熱・冷却性能は別に試作で確認します。

埋め込みPythonの終了時にQtがクラッシュする環境のため、検証プロセスでは文書を閉じて即時終了する回避策を使っています。回避策は設計コードには含めていません。通常の入口はFreeCADアプリ内のFCMacroです。
